# LeetCode 11 盛最多水的容器

## 我的思路（50分钟）
- 前30分钟：错误思路，试图同时维护左右最高值然后同时收缩边界，但面积计算逻辑混乱，一直调试不出来
- 中间10分钟：看答案，核心洞察——面积由短板决定，移动较长的一侧不可能获得更大面积（宽度已经减小，高度不会增加），所以应该移动较短的那一侧边界
- 后5分钟：根据短板思路修改通过
- 最后5分钟：增加剪枝优化——max_height * 当前宽度 <= ans 时直接 break，从 64ms 优化到 4ms

## 代码
```python
class Solution:
    def maxArea(self, height: List[int]) -> int:
        left, right = 0, len(height) - 1
        ans = 0
        max_height = max(height)
        
        while left < right:
            ans = max(ans, (right - left) * min(height[left], height[right]))
            # 剪枝：即使后续全部用最大高度，也无法超越当前答案
            if max_height * (right - left) <= ans:
                break
            # 移动较短的一侧
            if height[left] < height[right]:
                left += 1
            else:
                right -= 1
        
        return ans
```

## 关键
- 双指针：left 从 0 开始，right 从末尾开始，向中间收敛
- 短板效应：面积 = 宽度 × min(左高, 右高)，移动较长的一侧不可能获得更大面积
- 移动策略：height[left] < height[right] 则 left += 1，否则 right -= 1
- 剪枝优化：预计算 max_height，当 max_height * 剩余宽度 <= ans 时，后续不可能更优，直接 break

## 教训
- 看到"双指针求最大面积/容量" → 短板效应，只移动较短的那一侧
- 为什么移动短的：面积受限于 min(左, 右)，移动长的那一侧，宽度减小且高度不会增加（因为受限于另一侧的短高度），面积必然不会变大
- 剪枝思路：利用全局最大高度和当前宽度，计算理论最优上限，若上限 ≤ 当前答案则提前终止
- 和 42 题对比：42 接雨水是维护左右最高值向中间收拢（求能接多少水），11 是移动短板求最大面积（求最大容量）
