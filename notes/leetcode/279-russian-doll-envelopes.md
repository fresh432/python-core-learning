# LeetCode 354 俄罗斯套娃信封问题

## 我的思路（40分钟）
- 前20分钟：想到先给信封排序，维护一个当前子序列的尾部，遍历时比较尾部来添加计数并更新尾部；但这样会出现跳过最优解的情况，尾部的替换空间被定死了。又试了栈的方法也不行：出栈时会把原本可以算进去的数字弹掉
- 看答案20分钟：除了按第一维升序排序，还要按第二维降序。这样只看第二维排成的数组时，问题就转化为求它的最长递增子序列
  - 而第二维降序天然保证不会选同宽信封。然后维护一个 g 数组表示 LIS，遍历高度数组，用二分查找在 g 中找合适位置替换，这样尾部的选择空间更大
  - 找到的位置超过 g 长度说明子序列可拓展
  - 同宽信封因第二维降序，同一子序列只可能取其中一个，最后 g 的长度就是嵌套层数

## 代码
```python
class Solution:
    def maxEnvelopes(self, envelopes: List[List[int]]) -> int:
        envelopes.sort(key=lambda e: (e[0], -e[1]))   # 宽升序、高降序
        g = []
        for _, h in envelopes:                        # 高度数组求 LIS
            i, j = 0, len(g)
            while i < j:                              # 第一个 >= h 的位置
                mid = (i + j) // 2
                if g[mid] < h:
                    i = mid + 1
                else:
                    j = mid
            if j < len(g):
                g[j] = h                              # 替换，扩大尾部选择空间
            else:
                g.append(h)                           # 拓展子序列
        return len(g)
```

## 关键
- 二维偏序降维：第一维升序、第二维降序排序，把"信封嵌套"转成"高度的 LIS"
- 第二维降序的作用：同宽信封只可能取一个（高的先出现，后面矮的无法接续它），消除同宽干扰
- g 数组 + 二分替换 = O(n log n) 

## 教训
- 看到"二维嵌套/套娃" → 一维升序 + 另一维降序排序，转化为 LIS
- 自己"固定尾部"和"栈"失败的原因：都限制了替换空间，而LIS 的二分替换正是靠"允许替换中间位置"来保留更多可能性，这个 g 数组的灵活性是核心
