# LeetCode 879 盈利计划

## 我的思路（80分钟）
- 前40分钟：根据 0-1 背包模板写出大致框架，但犯了两个致命错误：
  - 目标理解错误：以为是求"最大利润"，实际是求"利润 ≥ minProfit 的方案总数"
  - 利润边界没处理：利润超过 minProfit 时应该按 minProfit 算，否则数组越界
- 后40分钟：看答案解析，修正认知——这是二维 0-1 背包计数问题，利润维度需要"封顶"处理

## 代码
```python
class Solution:
    def profitableSchemes(self, n: int, minProfit: int, group: List[int], profit: List[int]) -> int:
        MOD = 10 ** 9 + 7
        dp = [[0] * (n + 1) for _ in range(minProfit + 1)]
        dp[0][0] = 1  # 利润为0，使用0人，有1种方案（什么都不做）
        
        for i in range(len(group)):
            g = group[i]
            p = profit[i]
            
            for j in range(minProfit, -1, -1):
                nj = min(j + p, minProfit)  # 利润封顶，防止越界
                for k in range(n, g - 1, -1):
                    dp[nj][k] = (dp[nj][k] + dp[j][k - g]) % MOD
        
        return sum(dp[minProfit]) % MOD
```

## 关键
- 状态定义：dp[j][k] = 利润至少为 j，使用 k 个人的方案数
- 状态转移：dp[nj][k] += dp[j][k-g]
  - nj = min(j + p, minProfit)：利润超过目标后统一视为 minProfit，避免数组越界
  - k-g：使用当前组需要消耗 g 个人
- 初始化：dp[0][0] = 1（空方案），其余为 0
- 结果：sum(dp[minProfit]) —— 利润达到 minProfit，使用 0~n 任意人数的方案总数
- 两个维度都倒序：确保每个工作只选一次（0-1 背包）

## 教训
- 看到"给定人数上限、利润下限，求方案数" → 二维 0-1 背包计数
- 利润封顶技巧：nj = min(j + p, minProfit) 是处理"至少"类问题的经典做法，避免利润维度无限增长
- 目标类型判定：先确认题目要的是"最值"还是"方案数"，这直接决定 dp 的类型（整数计数 vs 布尔/最值）
- 和 474 题对比：两题都是二维 0-1 背包，但 474 是最值（max），879 是计数（sum）
