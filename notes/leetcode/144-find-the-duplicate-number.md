# LeetCode 287 寻找重复数

## 我的思路（45分钟）
- 前10分钟：想不出 O(n) 时间且 O(1) 空间的解法，排序或哈希表都不满足空间要求
- 中间30分钟：看答案，理解 Floyd 判圈算法——把数组值当作 next 指针，数组下标当作节点，重复数意味着有两个不同的下标指向同一个值（即同一个节点被两个节点指向），从而形成环
- 中间卡点：花时间思考"会不会在找到环之前就发生自环（nums[i] == i）导致算法卡住"。理解后发现不会：题目保证有重复数，且重复数一定形成环，快慢指针必然在环内相遇
- 后5分钟：自己写了一遍通过

## 代码
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        slow = fast = 0
        
        # Phase 1: 快慢指针找相遇点
        while True:
            slow = nums[slow]
            fast = nums[nums[fast]]
            if fast == slow:
                break
        
        # Phase 2: 找环入口（重复数）
        head = 0
        while slow != head:
            slow = nums[slow]
            head = nums[head]
        
        return slow
```

## 关键
- 数组 → 链表：把 nums[i] 看作节点 i 的 next 指针，即 i → nums[i]
- 重复数 → 环：两个不同的下标 i, j 满足 nums[i] == nums[j] == x，意味着两个节点都指向 x，形成环
- Floyd 判圈：
  - Phase 1：slow 走一步（nums[slow]），fast 走两步（nums[nums[fast]]），直到相遇
  - Phase 2：一个指针从起点（0）出发，另一个从相遇点出发，同步前进，相遇点即为环入口（重复数）

## 教训
- 看到"找重复数，要求 O(n) 时间 O(1) 空间" → Floyd 判圈算法，数组值当下标跳转
- 为什么不会自环卡住：即使存在 nums[i] == i 的自环，快慢指针的步长差异保证它们不会永远停留在自环上，最终会进入由重复数形成的大环
- 和 141/142 题对比：141 判断链表是否有环，142 找环入口，287 是数组版的 Floyd 判圈——本质完全相同，只是用数组值模拟 next 指针
